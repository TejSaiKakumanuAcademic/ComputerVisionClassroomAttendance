## Introduction
In a classroom setting attendance can be chaotic especially in large universities when enrollment is over 100 students. Our system seeks to streamline the process through an automated facial recognition system. The system utilizes a Python-based architecture to automate student check-ins through real-time image processing.

Student's faces will be scanned upon entering the class room. If the student is recognized they'll be marked as attendant. If the student is not recognized they'll be catalogued then marked as attendant.

## System Components
### Scripts
#### Recognize.py
Responsible for parsing incoming visual data from the environment to identify individuals. It compares captured facial scans against the known database. Upon a match, it triggers a request to the attendance script to log the entry. If no matches are found it triggers a request to the enroll script for onboarding.
#### Enroll.py
Handles the registration of new student faces. The script will parse the facial data and register it in the database. Then will request the attendance script to log the new face.
#### Attendance.py
Acts as a way to format attendance data for the attendance log csv. The scanned face will be logged alongside data and time.
#### Utils.py
Collection of utility functions. Mainly helper functions for use with OpenCV.
### Data
#### faces/
A directory acting as the primary database. It contains files containing student facial data alongside an ID for identification.
#### Attendance_Log.csv
The central comma separated database used for record-keeping. It stores fields such as Student_ID, Timestamp, and Attendance Status for review.

## Code Agent Interaction
Our team has decided to use Gemini as our model, with Google Antigravity as our agent environment. The agent will be restricted to only accessing files inside of the repository. All output generated by the Agent will be verified by a human editor to verify functionality.
